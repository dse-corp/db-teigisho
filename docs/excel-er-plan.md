# Excelで編集できるER図の生成計画

この文書は、XLSXの「ER図」シートを編集可能な図形にするために作成した計画の記録です。`er_xlsx.py`による図形生成と自動検証は実装済みです。以下の方針・作業順序・完了条件は計画時点の内容を残しています。実装との差分と未確認のExcel操作は[計画との照合結果](excel-er-verification.md)、現在の使い方は[ER図の操作と仕様](er-diagrams.md#excelで図形を編集する)を参照してください。

## 完成時の操作

テーブルを矩形・テキスト・区切り線で構成し、テーブルごとにグループ化する。FKはExcelのカギ線（直角に折れ曲がるコネクタ）で結ぶ。利用者はExcelでテーブルの位置、文字、色、線の折れ位置を編集できる。

- グループをドラッグすると、テーブル全体が移動し、接続されたコネクタの両端が追従する。
- グループ内のテキストを選択して、テーブル名やカラム名を編集できる。
- コネクタは独立して選択でき、線色・太さ・破線・折れ位置を変更できる。
- Excelで保存して開き直しても、図形・グループ・接続関係を維持する。

YAMLを引き続き定義の正本とする。Excelでの編集内容はYAMLへ取り込まず、再生成時はYAMLから図を作り直す。

## 表示内容

| 要素 | 構成・動作 |
| --- | --- |
| テーブル | 外枠、色付きヘッダー、カラム行、区切り線を1テーブル単位でグループ化 |
| ヘッダー | 物理名・論理名を編集可能な文字として表示 |
| カラム | 全カラムを表示。物理名、データ型、PK/FK/UKを既存の表記に合わせる |
| FK | FK定義1件につき1本の接続済みカギ線コネクタ。複合FKも1本とする |
| 線種 | 既存のERグラフが判定するidentifyingは実線、non-identifyingは破線 |
| 多重度 | `1`、`0..1`、`0..N`。端点側のテーブルに追従する文字として配置 |
| 関連の識別 | 接続口付近に関連番号を表示。FK名・参照元/参照先・列対応は図の下の凡例セルで確認 |
| 選択ウィンドウ | テーブルとFKを識別できるオブジェクト名を付与 |

多重度と関連番号は独立した固定位置のラベルにせず、対応するテーブルのグループに含める。コネクタの接続先を変更した場合のラベル修正は利用者が行う。

## 計画時点の実装と変更方針

計画作成時は`src/db_teigisho/render.py`の`_er_sheet()`がPNGを`A3`に貼り付けていた。印刷範囲も`A1:P45`に固定されていた。実装後はPNGの貼り付けを図形生成へ置き換え、印刷範囲を図と凡例から算出している。

`er_graph.py`にはFK・多重度・列対応があり、`er_scene.py`には文字計測と初期配置がある。これらを再利用して、Excel専用のDrawingML出力を追加する。

シートのセル・書式は引き続きopenpyxlで生成し、保存後のXLSXパッケージへ生成処理としてDrawingMLを組み込む。図形は`xdr:sp`、グループは`xdr:grpSp`、コネクタは`xdr:cxnSp`で表す。コネクタには`a:stCxn`・`a:endCxn`で接続先の図形IDと接続点を記録する。[図形間のコネクタ](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.spreadsheet.connectionshape?view=openxml-3.0.1)、[グループ図形](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.spreadsheet.groupshape?view=openxml-3.0.1)、[始点接続](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.startconnection?view=openxml-3.0.1)、[終点接続](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.endconnection?view=openxml-3.0.1)の公式仕様を参照する。

計画時に確認したopenpyxl 3.1.5の`SpreadsheetDrawing._write()`は画像とチャートを起点に書き出すため、図形出力の専用モジュールを設ける。図形追加後にopenpyxlで読み直して保存する工程は入れない。公式ドキュメントでも、既存ファイルを読み込んで保存すると図形が失われる場合があると説明されている。[openpyxlの制限](https://openpyxl.readthedocs.io/en/stable/tutorial.html#loading-from-a-file)

これはレンダラーによる自動生成処理とし、生成済みXLSXの手編集によって実装を管理しない。実行時はPythonだけで完結させ、Excelのインストールやマクロを生成の前提にしない。

## 実装順序

### 1. グループと接続の試作

2テーブルとFK1件で、グループ化した図形同士をカギ線で結ぶ最小ファイルを生成する。

- グループ内の外枠図形を接続先にした場合に、グループ全体の移動・拡縮へ線が追従するか確認する。
- 標準矩形の接続点と、複数FK用の接続点を設けた場合の動作を比較する。
- カギ線の標準形状（`bentConnector3`など）、方向、反転、折れ位置の設定を検証する。
- 自己参照と同一テーブル間の複数FKを追加し、別々の接続口で識別できるか確認する。
- Windows版・Mac版のデスクトップExcelで、移動、文字編集、折れ位置の調整、保存・再読込を確認する。

この段階で、接続対象となる子図形、接続点の割り当て、対応するカギ線形状を確定する。仕様上の接続IDが存在するだけでは操作要件の達成とみなさない。接続が維持できない構成は採用せず、グループ構成を修正して再検証する。

### 2. Excel専用図形レンダラー

新規モジュール`src/db_teigisho/er_xlsx.py`へ次の責務を集約する。

1. `ErGraph`と既存ノード配置から、テーブル図形と接続先を組み立てる。
2. ヘッダー・カラム・区切り線・端点ラベルをグループ内の相対座標で配置する。
3. 描画座標をEMUへ変換し、文字サイズはポイントで設定する。負座標も描画領域内へ平行移動する。
4. テーブル・子図形・コネクタへ、同一図内で重複しないIDと識別可能な名前を付与する。
5. FKごとに接続済みカギ線を生成する。コネクタはテーブルの背面へ配置する。
6. XMLはXMLライブラリで構築し、日本語、改行、`&`・`<`などを安全に扱う。

既存シーンの経路は任意の数の折れ点を持つため、単純に標準カギ線へ転記しない。初期経路と接続口の計算を参考に、試作で確認した標準カギ線へ変換する。自己参照には外側を回る経路を用意する。直線の寄せ集めで1本のFKを表現しない。

初期生成ではノードと線の重なりを検査し、必要に応じて間隔や折れ位置を調整する。利用者が移動した後の障害物回避や交差の再最適化はExcel側の動作に依存するため、アプリケーション固有の自動配置機能としては提供しない。

### 3. XLSX生成への統合

- `_er_sheet()`を、図形用シートの準備と凡例セルの出力へ変更する。
- `render_xlsx()`でERグラフと配置を取得し、PNG生成を経由せずに図形を生成する。
- 既存の`diagrams`引数を使う呼び出しとの互換性を維持し、画像を図形生成の入力にはしない。
- openpyxl保存後、ER図シートからのrelationship、DrawingML part、`[Content_Types].xml`を整合させてパッケージへ追加する。
- シート番号・DrawingMLファイル名・relationship IDは空きを割り当てる。同名ZIPエントリーの重複を作らない。
- 一時ファイルで生成と構造検証を完了してから出力先へ置き換える。
- 印刷範囲を図形の境界と凡例の末尾から算出する。大きな図は横1ページ・縦複数ページを基本とする。
- `build_artifacts()`では図形を組み込んだ最終XLSXに対してmanifestのハッシュを計算する。

初版は現在と同じ全カラム表示と既存CLIを使う。YAMLの項目・物理名、HTML/PDF/SVG/PNGの出力仕様は変更対象に含めない。

### 4. 検証とドキュメント

新規の`tests/test_er_xlsx.py`でパッケージと図形構造を検査し、既存のXLSXテストを更新する。

| 検証 | 合格条件 |
| --- | --- |
| 図形構造 | YAMLのテーブル数に対応するグループがあり、全カラムが編集可能なテキストで存在する |
| 接続構造 | FK数とコネクタ数が一致。各端点が存在する図形IDと有効な接続点を参照する |
| 特殊な関連 | 自己参照、循環参照、複数FK、複合FK、FKなしを扱える |
| 表記 | 実線/破線、多重度、PK/FK/UK、凡例の列対応がERグラフと一致する |
| 文字と寸法 | 長い日本語名、特殊文字、空の定義で破損・欠落・負の寸法を起こさない |
| パッケージ | XML・relationships・Content Typesが整合し、ER図の画像オブジェクトが存在しない |
| 既存出力 | シート順、定義書セル、数式に見える入力の文字列化、他形式、manifestが従来どおり機能する |
| 上限とオフライン | 既存のテーブル数・FK数上限で処理量を確認し、外部コマンド・通信なしで生成できる |

`tests/test_renderers.py`の画像数検査と、`tests/test_diagram_render.py`のXLSX画像検査を、DrawingMLの構造検査に置き換える。画像を生成する他形式の検査は維持する。XLSX単独生成でPNGレンダラーが呼ばれないことも確認する。

品質検査はRuff、mypy、pytest全体を実行する。代表例を`dbdef build`で再生成し、Excel実機で文字の欠け、接続の追従、カギ線の編集、保存後の維持、印刷を確認する。実機確認ができない場合は、その項目を未検証として明記し、XML検査だけで完了とはしない。

`README.md`、`docs/er-diagrams.md`、`docs/development.md`へ、Excelでの編集方法、再生成時の扱い、図形生成モジュールと検証方法を追記する。

## 完了条件

既存の`dbdef render ... --format xlsx`と`dbdef build`で、テーブルをグループ単位で移動でき、FKのカギ線が追従し、文字・書式・折れ位置を編集できるXLSXを生成できること。Excelで保存・再読込した後も、この操作が成立することを確認して完了とする。
